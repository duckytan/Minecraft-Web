## 🧭 按场景导航

### 场景 1：我是新加入的开发者，如何快速上手？

```
1. 阅读 README.md（了解项目概况）
2. 阅读 00 文档（配置开发环境）
3. 阅读 01-02 文档（理解需求与目标）
4. 阅读 06 文档（查看任务列表）
5. 阅读 08 文档（学习编码规范）
6. 开始开发首个任务
```

### 场景 2：我是 AI 执行代理，如何自动完成开发？

```
1. 读取 README.md，定位 11 号文档
2. 按照 11 号文档的执行清单逐步执行
3. 在执行过程中引用 02/03/04/05/06/08/09/10 文档获取细节
4. 执行完成后生成审计日志与交付报告
```

### 场景 3：我是产品经理，如何管理项目进度？

```
1. 参考 01 文档（项目章程与目标）
2. 参考 06 文档（任务清单与里程碑）
3. 参考 07 文档（工程管理流程）
4. 使用任务看板（GitHub Projects）跟踪进度
5. 查看 CHANGELOG.md 了解版本演进
```

### 场景 4：我是测试工程师，如何设计测试？

```
1. 阅读 02 文档（需求追踪矩阵）
2. 阅读 09 文档（测试策略与测试矩阵）
3. 参考 03/04 文档（架构与算法细节）
4. 编写测试用例并执行自动化测试
```

### 场景 5：我想部署这个项目，怎么操作？

```
1. 阅读 00 文档（环境准备）
2. 阅读 10 文档（部署流程）
3. 选择平台（GitHub Pages 或 Vercel）
4. 执行部署步骤
5. 配置监控与告警
```

## 📖 文档编写规范

1. 所有文档使用 Markdown 格式
2. 文档编号使用两位数（00-11）或字母前缀（A1/A2）
3. 文档之间通过相对路径互相引用
4. 每个文档包含目录、引用与下一步章节
5. 更新文档时同步更新版本号与最后修改时间

---

## 🔄 文档更新流程

1. 修改文档内容
2. 在文档底部更新版本号与时间
3. 在 CHANGELOG.md 记录变更
4. 提交到 Git 并说明变更原因
5. 通知相关干系人
