## 1. 部署策略概述

### 1.1 平台选择

| 平台 | 适用阶段 | 优势 | 限制 |
| --- | --- | --- | --- |
| **GitHub Pages** | MVP、演示 | 免费、简单、稳定 | 无服务器功能、100GB 流量限制 |
| **Vercel** | 生产、扩展 | CDN 加速、自动 HTTPS、支持 Serverless | 免费版 100GB 流量限制 |

### 1.2 部署拓扑

```
[开发分支 dev] → [CI 构建] → [测试环境]
                                     ↓
[主分支 main] → [CI 构建] → [预发布环境（可选）]
                                     ↓
                             [生产环境（GitHub Pages/Vercel）]
```

## 2. 构建流程

### 2.1 构建步骤

```bash
# 1. 安装依赖
npm install

# 2. 运行静态检查
npm run lint
npm run type-check  # 如使用 TS

# 3. 运行测试
npm run test

# 4. 构建生产版本
npm run build

# 5. 预览构建结果（可选）
npm run preview
```

### 2.2 构建产物

- 输出目录：`dist/`
- 主要文件：
  - `index.html`
  - `assets/*.js` （构建后的 JS Bundle）
  - `assets/*.css` （样式）
  - `assets/textures/` （纹理）

### 2.3 构建优化

```javascript
// vite.config.ts
import { defineConfig } from 'vite';

export default defineConfig({
  build: {
    target: 'es2015',
    minify: 'terser',
    rollupOptions: {
      output: {
        manualChunks: {
          three: ['three'],
        },
      },
    },
  },
});
```

## 3. GitHub Pages 部署

### 3.1 手动部署（零构建模式）

```bash
# 推送到 main 或 gh-pages 分支
git push origin main
```

在仓库设置 → Pages → 选择 `main` 分支根目录，点击 Save 即可。

### 3.2 自动部署（使用 GitHub Actions）

创建 `.github/workflows/deploy.yml`：

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches:
      - main

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - name: Setup Node.js
        uses: actions/setup-node@v3
        with:
          node-version: 18
          cache: 'npm'
      
      - name: Install dependencies
        run: npm ci
      
      - name: Build
        run: npm run build
      
      - name: Deploy to GitHub Pages
        uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./dist
```

### 3.3 访问地址

- `https://<username>.github.io/<repo-name>/`
- 可绑定自定义域名（在 `Settings` → `Pages` → `Custom domain`）

## 4. Vercel 部署

### 4.1 通过 Vercel Dashboard 部署

1. 登录 [vercel.com](https://vercel.com)
2. 点击 "Import Project"
3. 选择 GitHub 仓库
4. 配置构建设置：
   - Framework Preset：Vite
   - Build Command：`npm run build`
   - Output Directory：`dist`
5. 点击 "Deploy"

### 4.2 通过 Vercel CLI 部署

```bash
# 安装 Vercel CLI
npm install -g vercel

# 登录
vercel login

# 构建与部署
npm run build
vercel --prod
```

### 4.3 配置文件（vercel.json）

```json
{
  "version": 2,
  "buildCommand": "npm run build",
  "outputDirectory": "dist",
  "devCommand": "npm run dev",
  "installCommand": "npm install",
  "framework": "vite",
  "routes": [
    {
      "src": "/(.*)",
      "dest": "/index.html"
    }
  ]
}
```

## 5. 环境变量与配置

### 5.1 环境变量定义

| 变量 | 说明 | 示例 | 环境 |
| --- | --- | --- | --- |
| `VITE_ENV` | 环境标识 | `dev`, `prod` | 所有 |
| `VITE_RENDER_DISTANCE` | 渲染距离 | `4` | 生产 |
| `VITE_DEBUG` | 调试模式 | `true` | 开发 |

### 5.2 使用方式

```typescript
// src/config/index.ts
export const CONFIG = {
  renderDistance: parseInt(import.meta.env.VITE_RENDER_DISTANCE || '4'),
  debug: import.meta.env.VITE_DEBUG === 'true',
};
```

### 5.3 平台配置

- **GitHub Actions**：在 `workflow` 文件中设置 `env`
- **Vercel**：在 Dashboard → Settings → Environment Variables

## 6. 监控与告警

### 6.1 Vercel Analytics

- 自动启用（项目设置中）
- 查看访问量、页面性能
- Dashboard：[vercel.com/analytics](https://vercel.com/analytics)

### 6.2 自定义监控

```typescript
// 错误上报（可选集成 Sentry）
window.addEventListener('error', (event) => {
  console.error('Global Error:', event.error);
  // 可发送至监控服务
});

// 性能监控
const observer = new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    console.log('Performance:', entry);
  }
});
observer.observe({ entryTypes: ['navigation', 'resource'] });
```

### 6.3 告警机制

- **Vercel**：配置通知渠道（Email、Slack）
- **自定义**：使用 Webhook 向监控平台推送事件

## 7. 日志与排查

### 7.1 日志分级

| 级别 | 用途 |
| --- | --- |
| `DEBUG` | 开发调试 |
| `INFO` | 一般信息 |
| `WARN` | 警告（不影响功能） |
| `ERROR` | 错误（影响功能） |

### 7.2 日志实现

```typescript
// src/utils/logger.ts
class Logger {
  private static enabled = import.meta.env.VITE_DEBUG === 'true';

  static debug(...args: any[]) {
    if (this.enabled) console.log('[DEBUG]', ...args);
  }

  static warn(...args: any[]) {
    console.warn('[WARN]', ...args);
  }

  static error(...args: any[]) {
    console.error('[ERROR]', ...args);
  }
}
```

### 7.3 排查流程

```
1. 查看浏览器 Console 日志
2. 打开 DevTools Network 面板（检查资源加载）
3. 查看 Performance 面板（定位性能问题）
4. 检查 Vercel/GitHub Pages 部署日志
5. 分析错误栈，定位代码行
```

## 8. 上线与回滚流程

### 8.1 上线前检查清单

```
[ ] 通过 lint、test、build
[ ] 性能测试达标
[ ] 功能验收通过
[ ] Release Note 编写完成
[ ] 数据备份（如有）
[ ] 确认上线窗口（避免高峰期）
```

### 8.2 上线流程

```
1. 合并代码至 main 分支
2. 打 Git Tag：git tag v1.0.0 && git push --tags
3. 触发 CI/CD 部署
4. 验证部署结果（访问生产 URL）
5. 监控日志与性能（首 30 分钟）
6. 记录上线时间与版本号
```

### 8.3 回滚流程

**GitHub Pages**：
```bash
# 回退至上一版本
git revert <commit-hash>
git push origin main
```

**Vercel**：
- 在 Vercel Dashboard → Deployments
- 选择上一个稳定版本，点击 "Promote to Production"

## 9. 备份与灾难恢复

### 9.1 备份策略

| 备份内容 | 频率 | 存储位置 |
| --- | --- | --- |
| 代码仓库 | 每次提交 | GitHub（自动） |
| 构建产物 | 每次部署 | Vercel（自动保留） |
| 用户存档 | 本地存储 | 用户浏览器（提供导出功能） |

### 9.2 灾难恢复

- **仓库误删**：GitHub 有 90 天恢复期
- **部署失败**：使用回滚流程
- **用户数据丢失**：提供存档导出/导入功能

## 10. 安全加固

### 10.1 HTTPS

- GitHub Pages 与 Vercel 自动提供 HTTPS

### 10.2 CSP（内容安全策略）

```html
<!-- index.html -->
<meta http-equiv="Content-Security-Policy" 
      content="default-src 'self'; 
               script-src 'self' https://cdn.jsdelivr.net; 
               style-src 'self' 'unsafe-inline'; 
               img-src 'self' data:;">
```

### 10.3 输入校验

- 配置面板输入必须验证（如渲染距离范围）
- 防止 XSS（不使用 `innerHTML` 插入用户内容）
