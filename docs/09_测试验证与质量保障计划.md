## 1. 测试策略总览

### 1.1 测试金字塔

```
       ┌────────────────────────────┐
       │      端到端测试 (E2E)        │ 10%
       ├────────────────────────────┤
       │     集成测试 + Snapshot     │ 30%
       ├────────────────────────────┤
       │        单元测试 (Unit)      │ 60%
       └────────────────────────────┘
```

### 1.2 测试目标

1. 功能正确性：确保所有核心用例（需求文档 02）可用
2. 性能指标：首屏 3s 内，FPS ≥ 60（主机）
3. 稳定性：无崩溃、内存泄漏
4. 兼容性：主流浏览器正常运行

| TC-UNIT-002 | Terrain | `generateFlatTerrain` 生成正确层级 |
| TC-UNIT-003 | Collision | `intersects` 判定相交 |

import { describe, it, expect } from 'vitest';

describe('Terrain', () => {
  it('should generate correct block layers', () => {
    const blocks = generateFlatTerrain(0, 0);
    const topBlocks = blocks.filter(block => block.position[1] === 3);

## 5. 自动化测试流程

### 5.1 流程概览

```
[提交代码] → [触发 CI] → [安装依赖] → [lint] → [test] → [build] → [生成报告]
```

### 5.2 GitHub Actions 配置示例

```yaml
name: CI

on:
  push:
    branches: [ main, dev ]
  pull_request:
    branches: [ main, dev ]

jobs:
  build-and-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
        with:
          node-version: 18
      - run: npm install
      - run: npm run lint
      - run: npm run test -- --coverage
      - run: npm run build
      - uses: actions/upload-artifact@v3
        with:
          name: coverage-report
          path: coverage
```

### 5.3 覆盖率标准

| 指标 | 目标 |
| --- | --- |
| 语句覆盖率 | ≥ 70% |
| 分支覆盖率 | ≥ 60% |
| 函数覆盖率 | ≥ 70% |
| 行覆盖率 | ≥ 70% |

## 6. 性能测试计划

### 6.1 指标

| 指标 | 目标 | 工具 |
| --- | --- | --- |
| 首屏加载时间 | ≤ 3s | Lighthouse |
| 交互延迟（FID） | ≤ 100ms | Lighthouse |
| 每帧渲染时间 | ≤ 16ms | Chrome Performance |
| 内存占用 | ≤ 500MB | Chrome Task Manager |
| FPS（主机） | ≥ 60 | stats.js |

### 6.2 测试流程

1. 构建生产版本：`npm run build`
2. 使用 `npm run preview`
3. 运行 Lighthouse CLI：`lighthouse http://localhost:4173 --view`
4. 使用 `Chrome DevTools` Record 10 秒游戏过程
5. 分析 CPU/内存占用

### 6.3 性能优化建议

- 启用 Chunk 与面剔除
- 限制渲染距离
- 延迟加载非关键资源
- 使用 requestIdleCallback 处理后台任务

## 8. 缺陷管理与质量门禁

### 8.1 缺陷管理流程

```
[发现缺陷] → [记录 Issue] → [评估优先级] → [修复] → [回归测试]
```

- Issue 模板：重现步骤、预期结果、实际结果、环境、日志
- 缺陷优先级：P0（阻塞）、P1（严重）、P2（一般）、P3（轻微）

### 8.2 质量门禁

| 阶段 | 门禁条件 |
| --- | --- |
| 合并到 dev 分支 | Lint、Unit Test 必须通过 |
| 合并到 main 分支 | Lint、Unit、Integration、Build 通过；关键 E2E 测试通过 |
| 发布生产环境 | Regression 测试通过；PO 验收；性能指标达标 |
