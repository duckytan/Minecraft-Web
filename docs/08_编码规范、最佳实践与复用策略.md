## 1. 代码风格规范

### 1.1 基础规则

- **语言**：TypeScript（推荐）/ JavaScript（MVP 可用）
- **缩进**：2 空格
- **引号**：单引号（`'`）
- **行宽**：80-100 字符（推荐 80）
- **分号**：必须使用
- **尾部逗号**：多行时使用

### 1.2 ESLint 配置

```javascript
// .eslintrc.js

  extends: [

    'semi': ['error', 'always'],
    'comma-dangle': ['error', 'always-multiline'],
    'no-console': ['warn', { allow: ['warn', 'error'] }],
  },
};
```

## 2. 命名规范

### 2.1 命名约定

| 类型 | 规则 | 示例 |
| --- | --- | --- |
| 变量、函数 | camelCase | `playerPosition`, `createScene()` |
| 类、接口 | PascalCase | `World`, `BlockProperties` |
| 常量 | UPPER_SNAKE_CASE | `CHUNK_SIZE`, `GRAVITY` |
| 私有成员 | 前缀 `_` | `_internalState` |
| 文件名 | kebab-case | `chunk-manager.ts` |

### 2.2 命名原则

1. **见名知义**：名称应清楚描述用途
2. **避免缩写**：除非是广泛接受的缩写（如 `FPS`, `UI`）
3. **动词+名词**：函数名如 `getBlock`, `createChunk`

```typescript
// ✅ 推荐
function calculatePlayerVelocity(delta: number): Vector3 { }

// ❌ 不推荐
function calc(d: number) { }
```

## 3. 模块化与目录组织

### 3.1 标准目录结构

```
src/
├── main.ts              # 应用入口
├── core/                # 核心场景、渲染器
│   ├── scene.ts
│   ├── camera.ts
│   └── renderer.ts
├── world/               # 世界生成、Chunk
│   ├── index.ts
│   ├── chunk.ts
│   ├── terrain.ts
│   └── meshing.ts
├── player/              # 玩家控制
│   └── index.ts
├── physics/             # 物理、碰撞
│   └── collision.ts
├── input/               # 输入处理
│   ├── keyboard.ts
│   └── mouse.ts
├── ui/                  # UI 组件
│   ├── hud.ts
│   └── hotbar.ts
├── storage/             # 存档
│   └── index.ts
├── config/              # 配置
│   └── index.ts
├── utils/               # 工具函数
│   └── math.ts
└── types/               # TypeScript 类型定义
    └── index.ts
```

### 3.2 模块导出规范

- 每个模块使用 `index.ts` 导出公共 API
- 内部实现隐藏，避免外部依赖

```typescript
// src/world/index.ts
export { World } from './world';
export { Chunk } from './chunk';
export * from './types';
```

## 4. Three.js 最佳实践

### 4.1 对象管理

```typescript
// ✅ 及时清理资源
function removeBlock(block: Block) {
  block.mesh.geometry.dispose();
  block.mesh.material.dispose();
  scene.remove(block.mesh);
}
```

### 4.2 几何体复用

```typescript
// ✅ 共享 Geometry
const blockGeometry = new THREE.BoxGeometry(1, 1, 1);
for (const block of blocks) {
  const mesh = new THREE.Mesh(blockGeometry, material);
  scene.add(mesh);
}
```

### 4.3 使用 BufferGeometry

```typescript
// ✅ 性能更好
const geometry = new THREE.BufferGeometry();
geometry.setAttribute('position', new THREE.Float32BufferAttribute(positions, 3));
```

## 5. 性能优化指南

| 技术 | 说明 | 影响 |
| --- | --- | --- |
| **Chunk 系统** | 按需加载/卸载 | 减少渲染负担 |
| **面剔除** | 不渲染隐藏面 | 减少三角形数 |
| **InstancedMesh** | 批量渲染相同对象 | 减少 Draw Call |
| **纹理图集** | 合并纹理 | 减少纹理切换 |
| **Web Worker** | 后台计算 | 避免主线程阻塞 |
| **LOD** | 远处用简化模型 | 减少顶点数 |

### 5.1 性能检查清单

- [ ] 使用 `stats.js` 监控 FPS
- [ ] 使用 Chrome DevTools Performance 分析瓶颈
- [ ] 控制场景对象数量 ≤ 50K 三角形（移动端 ≤ 10K）
- [ ] 限制每帧 Draw Call ≤ 100
- [ ] 纹理尺寸尽量 ≤ 1024x1024

## 7. 注释与文档

### 7.1 JSDoc 规范

```typescript
/**
 * 生成平坦地形
 * @param chunkX Chunk X 坐标
 * @param chunkZ Chunk Z 坐标
 * @returns 方块数据数组
 */
function generateFlatTerrain(chunkX: number, chunkZ: number): Block[] {
  // 实现
}
```

### 7.2 注释原则

1. **Why > What**：解释为什么，而非做什么
2. **复杂逻辑必注释**：如面剔除算法、碰撞检测
3. **TODO 标记**：待完成事项

```typescript
// TODO: 优化碰撞检测算法，使用空间划分
```

## 9. Git 提交规范


## 10. 复用策略与设计模式

### 10.1 设计模式应用

| 模式 | 应用场景 | 示例 |
| --- | --- | --- |
| **单例模式** | 全局配置、事件总线 | `Config.getInstance()` |
| **工厂模式** | 方块创建 | `BlockFactory.create(type)` |
| **观察者模式** | 事件系统 | `EventEmitter` |
| **策略模式** | 地形生成器切换 | `TerrainGenerator` 接口 |

### 10.2 代码复用原则

1. **DRY（Don't Repeat Yourself）**：避免重复代码
2. **KISS（Keep It Simple, Stupid）**：保持简单
3. **SOLID 原则**：尤其是单一职责、开闭原则
