## 3. 开发执行步骤

```
Step 1: 同步任务
    - 打开 06 文档，选择当前迭代任务
    - 在任务管理工具创建/更新卡片

Step 2: 创建分支
    - git checkout -b feature/<task-id>

Step 3: 实施任务
    - 按 06 文档中对应任务的实施步骤执行
    - 参考 03/04/05 文档获取技术细节
    - 编写代码时遵循 08 文档的规范

Step 4: 编写/更新测试
    - 根据 09 文档新增或更新测试用例

Step 5: 运行本地验证
    - npm run lint
    - npm run test
    - npm run build

Step 6: 更新文档（如需要）
    - 修改相关文档，记录变更
    - 更新 CHANGELOG（如涉及版本）
```

---

## 4. 测试与质量保障步骤

```
Step 7: 生成测试报告
    - npm run test -- --coverage
    - 保存 coverage 报告（如需）

Step 8: 准备 PR
    - git add .
    - git commit -m "feat(scope): 描述"
    - git push origin feature/<task-id>
    - 创建 PR，关联 Issue/任务

Step 9: 等待 CI 结果
    - 检查 GitHub Actions Lint/Test/Build
    - 若失败：分析日志，修复后重新推送

Step 10: 代码评审
    - 提供变更描述、测试结果、截图（如 UI）
    - 响应评审意见
```

---

## 5. 部署与交付步骤

```
Step 11: 合并代码
    - CI 通过后，由 TL/AI 工具合并到 dev/main

Step 12: 执行部署
    - GitHub Pages: 自动或手动触发工作流
    - Vercel: 自动部署或 `vercel --prod`

Step 13: 部署验证
    - 打开生产 URL 验证功能
    - 检查监控、错误日志

Step 14: 更新版本信息
    - 更新 Release Note（如正式发布）
    - 打 Tag：git tag vX.Y.Z && git push --tags

Step 15: 用户通知（可选）
    - 发送更新通知、发布说明
```

## 6. 回滚与故障处理

```
[ ] 监控发现异常或用户反馈
[ ] 判断影响范围与严重性
[ ] 启动回滚（GitHub Pages 或 Vercel）
[ ] 创建 Incident 记录，分析根因
[ ] 制定修复计划，进入新一轮迭代
```

---

## 7. 日志记录要求

- **执行日志**：
  - 时间戳、执行命令、结果
  - 保存到 `logs/ai-run-<date>.log`
- **错误日志**：
  - 捕获异常信息、堆栈
  - 上报至监控系统（如配置）
- **审计记录**：
  - PR 链接、CI 结果、部署记录
