## 1. 架构设计原则

1. **Serverless First**：不依赖后端服务，所有逻辑在前端执行
2. **模块化 & 可扩展**：核心功能模块独立，支持未来扩展（多人联机、模组）
3. **性能优先**：针对 WebGL 场景设计，尽量减少 Draw Call、内存占用
4. **渐进式增强**：MVP -> 优化 -> 扩展，保持各阶段可用
5. **AI 友好**：实现路径清晰、接口规范明确、文档可解析

| 部署平台 | GitHub Pages / Vercel | 静态托管 |

## 3. 系统架构总览

```
┌──────────────────────────────────────────┐
│                Web 前端（全部代码）      │
│  ┌─────────────┐   ┌──────────────────┐  │
│  │   核心逻辑  │   │   辅助与工具模块 │  │
│  │             │   │                  │  │
│  │ ┌────────┐ │   │ ┌──────────────┐ │  │
│  │ │ 渲染层 │ │   │ │ 存档管理     │ │  │
│  │ │        │ │   │ │ 配置与设置   │ │  │
│  │ │ 世界   │ │   │ │ 日志与调试   │ │  │
│  │ │ 玩家   │ │   │ │ 性能监控     │ │  │
│  │ └────────┘ │   │ └──────────────┘ │  │
│  └─────────────┘   └──────────────────┘  │
│                                              │
│      ▼ 数据持久化（LocalStorage / IndexedDB） │
└──────────────────────────────────────────┘
```

- **渲染层**：Three.js 场景、相机、渲染器、光照配置

- **玩家模块**：输入处理、物理、碰撞检测
- **UI 模块**：HUD、菜单、提示
- **工具模块**：日志、配置、事件总线
- **存档模块**：序列化、存储、加载

## 4. 模块设计详解

### 4.1 模块列表

| 模块 | 目录建议 | 职责 | 关键接口 |
| --- | --- | --- | --- |
| **App Root** | `src/main.ts` | 应用入口、初始化 | `bootstrap()` |
| **Scene** | `src/core/scene.ts` | 创建场景、相机、光照 | `createScene()`, `createCamera()` |
| **Renderer** | `src/core/renderer.ts` | 初始化渲染器、窗口缩放 | `createRenderer()`, `resizeRendererToDisplaySize()` |
| **World** | `src/world/index.ts` | 管理 Chunk、方块数据 | `loadChunk()`, `setBlock()`, `removeBlock()` |
| **Terrain** | `src/world/terrain.ts` | 地形生成算法 | `generateHeight(x,z)` |
| **Player** | `src/player/index.ts` | 控制输入、移动、碰撞 | `update(delta)`, `handleInput()` |
| **Input** | `src/input/keyboard.ts`, `mouse.ts` | 键鼠事件监听 | `registerKeyBindings()` |
| **Physics** | `src/physics/collision.ts` | AABB 检测、重力 | `checkCollision(box)` |
| **UI** | `src/ui/hud.ts` | HUD 渲染、交互提示 | `renderHUD()` |
| **Storage** | `src/storage/index.ts` | 存档序列化、持久化 | `saveWorld()`, `loadWorld()` |
| **Config** | `src/config/index.ts` | 全局配置管理 | `getConfig()`, `updateConfig()` |
| **Utils** | `src/utils/` | 工具函数 | 随模块引用 |

### 4.2 模块关系（依赖图）

```
App Root
 ├─ Scene
 │   └─ Renderer
 ├─ World
 │   ├─ Terrain
 │   ├─ Physics
 │   └─ Storage
 ├─ Player
 │   ├─ Input
 │   └─ Physics
 └─ UI
     ├─ Config
     └─ Storage
```

### 4.3 模块接口示例

```typescript
// src/world/index.ts
export interface Block {
  position: { x: number; y: number; z: number };
  type: BlockType;
}

export class World {
  constructor(private chunkManager: ChunkManager) {}

  getBlock(position: Vector3): Block | null;
  setBlock(position: Vector3, blockType: BlockType): void;
  removeBlock(position: Vector3): void;
  update(delta: number): void;
}
```

## 5. 数据流与状态管理

### 5.1 数据流

```
[输入设备] → [Input 模块] → [Player 模块] → [Physics] → [World/Chunk]
                                        ↓
                                     [UI/HUD]
                                        ↓
                                    [Renderer]
```

### 5.2 状态管理

| 状态域 | 描述 | 存储位置 | 同步机制 |
| --- | --- | --- | --- |
| **玩家状态** | 位置、旋转、速度、库存 | 内存（Player 模块）、存档 | 每帧更新、定时保存 |
| **世界状态** | Chunk 数据、方块类型 | 内存（World 模块）、IndexedDB | 按需加载/卸载 |
| **配置状态** | 渲染距离、FOV、灵敏度 | Config 模块、LocalStorage | UI 修改时同步 |
| **UI 状态** | HUD 显示、提示信息 | UI 模块 | 事件触发更新 |

### 5.3 事件与通信

- 使用 `EventEmitter` 或自定义事件系统协调模块
- 关键事件：`BLOCK_PLACED`、`BLOCK_REMOVED`、`PLAYER_MOVE`、`CHUNK_LOADED`

## 6. 性能优化策略

| 优化项 | 描述 | 参考实现 |
| --- | --- | --- |
| **Chunk 系统** | 将世界按 16x16x16 划分，按需加载 | `src/world/chunk.ts` |
| **面剔除** | 只渲染外露面，减少三角形数量 | `src/world/meshing.ts` |
| **InstancedMesh** | 相同方块合并渲染 | Optional：`THREE.InstancedMesh` |
| **LOD** | 远景使用低细节模型 | 可选特性 |
| **Web Worker** | 将地形生成放入 Worker | `src/workers/terrain.worker.ts` |
| **配置参数** | 渲染距离、粒度 | `Config` 模块 |

## 9. 扩展性设计与接口

### 9.1 模块扩展点

- `World`：支持不同地形生成器、方块类型
- `Player`：可扩展为多人控制
- `UI`：可增加背包系统、合成系统
- `Storage`：接入云存储或服务器同步

## 10. 安全与容错设计

| 风险 | 缓解策略 |
| --- | --- |
| 浏览器崩溃 | 自动保存机制、错误恢复 |
| 数据损坏 | 多份存档、校验和 |
| XSS 风险 | 严格使用模块化，不引入未校验脚本 |
| 性能突降 | 回退渲染距离、动态调整 |

## 11. 架构决策记录（ADR）摘要

| 编号 | 决策 | 结论 | 影响 |
| --- | --- | --- | --- |
| ADR-001 | Three.js vs Babylon.js | 选择 Three.js | 文档丰富、社区大 |
| ADR-002 | TypeScript 引入时机 | Iteration 2 起 | 先实现 MVP，再增 TS |
| ADR-003 | 存档机制 | IndexedDB + LocalStorage | 按需扩展 |
| ADR-004 | 构建工具 | 采用 Vite | 快速开发、内置优化 |
| ADR-005 | Chunk 大小 | 16x16x16 | 平衡性能与复杂度 |
